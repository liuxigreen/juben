# 阶段2技术文档：SmartAdapter v2 — 分镜转换引擎

## 1. 定位

SmartAdapter是剧本→分镜的转换引擎，负责将纯文本剧本（阶段1输出）转换为结构化分镜数据（阶段3输入）。

```
阶段1 剧本写作 → 【阶段2 SmartAdapter】 → 阶段3 提示词生成
                  ↑ 我们在这里
```

## 2. 核心问题：旧版为什么坏了

旧版adapter.py是"瞎子"——不看剧本内容，硬编码一切：

| 问题 | 旧版行为 | 正确行为 |
|---|---|---|
| 场景切分 | 按段落硬切，1580字切15个场景 | 语义识别，只在换地点时切 |
| 位置检测 | 硬编码10个关键词（《大厂修仙》专用） | 从locations.json动态加载 |
| 角色注入 | 全部为空 | 从characters.json匹配 |
| 景别选择 | 不看内容，按卡点位置硬套 | 根据情绪+场景类型选值 |
| 运镜选择 | 同上 | 根据情绪+叙事位置选值 |
| 光影选择 | 不选（空） | 根据情绪基调选值 |
| 时长分配 | 全部18秒 | 根据内容密度动态计算 |
| 对话提取 | "嗒嗒"误识别为台词 | 过滤声效拟声词 |
| 画面动作 | "他的语速比平时更慢"（不可拍） | 只提取物理可拍摄动作 |

**根因**：旧版没有"场景提取"这一步，直接从段落跳到镜头，中间丢失了全部语义信息。

## 3. 架构设计

### 3.1 三阶段流水线

```
纯剧本
  │
  ▼
┌─────────────────────────────────┐
│ Stage 1: 场景提取 (SceneExtractor) │
│   规则+正则，零LLM调用           │
│   输入: 纯文本                    │
│   输出: list[SceneUnit]          │
└─────────────────────────────────┘
  │
  ▼
┌─────────────────────────────────┐
│ Stage 2: 镜头设计 (ShotDesigner)  │
│   语义分析，零LLM调用             │
│   输入: list[SceneUnit]          │
│   输出: list[ShotDesign]         │
└─────────────────────────────────┘
  │
  ▼
┌─────────────────────────────────┐
│ Stage 3: 组装输出 (EpisodeAdapter)│
│   兼容Episode schema             │
│   输出: Episode JSON             │
└─────────────────────────────────┘
  │
  ▼
下游: ShotPromptGenerator → AI视频提示词
```

### 3.2 关键类

| 类 | 职责 | 输入 | 输出 |
|---|---|---|---|
| `SceneExtractor` | 场景提取 | 纯文本 | `list[SceneUnit]` |
| `ShotDesigner` | 镜头设计 | `list[SceneUnit]` | `list[ShotDesign]` |
| `EpisodeAdapter` | 主适配器（对外接口） | 纯文本 | `Episode` |

## 4. Stage 1: 场景提取

### 4.1 切割策略

**核心原则**：只在真正换地点时才切场景。

```
旧版: "他站起来" → 切！"她转身" → 切！"走出门" → 切！
      结果: 1580字切15个场景，平均每场景105字

新版: "他站起来" → 不切（还在面馆）
      "巷子里没有路灯" → 切！（检测到"巷子"关键词）
      结果: 1580字切3-5个场景，每场景300-500字
```

### 4.2 场景切换信号

| 信号 | 触发条件 | 示例 |
|---|---|---|
| 位置变化 | 检测到新位置关键词 ≠ 当前位置 | "面馆"→"巷子" |
| 时空跳跃 | 段落以标记开头 + 有位置信息 | "第二天，回到咖啡店" |

### 4.3 位置检测

从`locations.json`动态加载，支持两种格式：

```json
// 格式1: 简单列表（自动扩展别名）
{"locations": ["念想咖啡店", "面馆", "巷子"]}

// 格式2: 关键词映射（精确控制）
{"念想咖啡店": ["吧台", "磨豆", "杯壁"], "面馆": ["面碗", "排风扇"]}
```

### 4.4 小场景合并

< 200字的场景自动并入相邻场景，避免过度碎片化。

## 5. Stage 2: 镜头设计

### 5.1 四大维度选值逻辑

#### 景别（ShotType）

```
情绪优先:  震惊/愤怒/悲伤/恐惧 → CU（特写）
           紧张/暧昧/中性 → MCU（近景）
           日常 → MS（中景）

场景兜底:  对话 → MCU | 动作 → MS | 悬念 → CU
```

#### 运镜（CameraMovement）

```
情绪驱动:  震惊/愤怒/紧张/悬疑 → Push（推镜）
           悲伤/暧昧 → Pull（拉镜）
           恐惧 → Handheld（手持）
           日常 → Static（静止）

叙事覆写:  最后一个场景+有钩子 → Push（强制悬念感）
```

#### 视角（CameraAngle）

```
愤怒/紧张 → Low Angle（仰拍，压迫感）
悲伤/恐惧 → High Angle（俯拍，渺小感）
其他 → Eye Level（平视）
```

#### 光影（Lighting）

```
震惊/愤怒/紧张 → High contrast（高对比）
悲伤/恐惧/悬疑 → Low key（冷调）
暧昧 → Warm（暖光）
日常 → Natural（自然光）
```

### 5.2 时长分配

旧版：全部18秒（5×18=90）

新版：
```
1. 计算目标镜头数 = 总字数 ÷ 200（最少3，最多8）
2. 每个镜头基础时长 = 90 ÷ 目标镜头数
3. 按比例缩放使总时长 = 90秒
```

### 5.3 音效选择

优先从文本中提取具体音效（"嗡嗡"→electrical hum），兜底用情绪→音效映射。

## 6. 输出格式

兼容Episode schema，可直接喂给`ShotPromptGenerator`：

```json
{
  "episode_number": 9,
  "duration_estimate_seconds": 90,
  "shots": [
    {
      "shot_id": 1,
      "shot_type": "CU",
      "camera_movement": "static",
      "camera_angle": "eye-level",
      "duration": 15.0,
      "action": "苏念坐在对面，手里攥着一双没拆封的一次性筷子",
      "lighting": "Natural",
      "location": "面馆",
      "characters_present": ["苏念", "顾深"],
      "audio_prompt": "electrical hum",
      "dialogue": "巧合。",
      "emotion_tag": "日常",
      "pacing_label": "3s_Hook"
    }
  ],
  "cliffhanger": {"type": "shock", "line": "..."}
}
```

## 7. 与旧版对比

| 维度 | 旧Adapter | SmartAdapter v2 |
|---|---|---|
| 场景切分 | 按段落硬切(15个) | 语义识别(3-5个) |
| 位置检测 | 硬编码(全部失败) | 动态加载(正确) |
| 角色注入 | 空 | 从characters.json匹配 |
| 景别/运镜/光影 | 不选或硬编码 | 语义驱动选值 |
| 时长 | 全部18秒 | 动态计算 |
| 对话 | 声效误识别 | 过滤声效 |
| 画面动作 | 抽象描述 | 只取可拍摄影像 |
| LLM依赖 | 无 | 无 |
| 成本 | 零 | 零 |

## 8. 与scribe_prompt.py的关系

| | scribe_prompt.py | SmartAdapter |
|---|---|---|
| 方式 | 5000token大prompt → LLM转分镜 | 纯规则+正则 |
| 画面质感 | ⭐⭐⭐⭐⭐ 电影级 | ⭐⭐⭐ 可用 |
| 成本 | 每章1次LLM调用 | 零 |
| 速度 | 慢（等LLM） | 快（毫秒级） |
| 稳定性 | LLM输出不稳定 | 确定性输出 |

**结论**：SmartAdapter做骨架（80%），scribe_prompt.py的小prompt补画面（20%）。大prompt不再需要。

## 9. 后续优化方向

1. **Stage 3画面补全**：接入小prompt（500token），只补光影+音效+视角细节
2. **位置检测增强**：从剧本中自动学习位置关键词，不依赖手动配置
3. **情绪检测增强**：接入更细粒度的情绪分析（复合情绪、情绪转折）
4. **时长优化**：根据节奏卡点规则动态调整（Hook场景更短，Cliffhanger更长）
5. **多章连续性**：跨镜头角色视觉一致性追踪
