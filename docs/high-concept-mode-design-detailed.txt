## 一、问题背景与诊断
================================================================================

### 1.1 核心问题

传统AI在生成剧本大纲时存在三大根本性缺陷：

**问题1：平庸化**
- AI倾向于选择"安全"的、"最大公约数"式的创意
- 原因：训练数据中常见模式占比高，AI学习后复制
- 表现：生成的故事缺乏突破性，观众看了开头就知道结尾

**问题2：套路化**
- AI会重复使用训练数据中常见的模式
- 原因：AI没有"创新"的概念，只有"概率最高"的选择
- 表现：所有故事都是同一个模板，换皮不换骨

**问题3：缺乏商业Hook**
- AI不理解"什么能让观众点击"，只关注"逻辑自洽"
- 原因：AI没有"观众心理"的概念，只有"语法正确"
- 表现：故事逻辑完整但无聊，观众没有点击欲望

### 1.2 问题根源

AI的本质是"模式匹配器"，不是"创意生成器"：
- AI擅长：从训练数据中找到最可能的模式
- AI不擅长：创造训练数据中不存在的新模式
- 结果：AI生成的内容是"平均值"，不是"峰值"

### 1.3 解决思路

**核心理念：创意结构 ≠ 剧情细节**

- 创意结构是骨架：决定故事的吸引力（可标准化）
- 剧情细节是血肉：决定故事的独特性（需AI发挥）
- 解决方案：人类设计骨架，AI填充血肉

**实施策略：在Bootstrap的第一秒，强制注入高反差、强视觉、极具商业Hook的创意结构**

## 二、高概念模式四大组件
================================================================================

### 2.1 高概念种子（Core Hook Seed）

#### 2.1.1 定义

一句话描述故事的核心吸引力，必须同时满足三个条件：

1. **高反差**：两个极端元素的碰撞
   - 示例：外卖员 vs 连环杀手
   - 示例：乞丐 vs 总裁
   - 示例：学生 vs 黑帮老大

2. **强视觉**：必须能用一个画面概括
   - 示例：外卖员在凶案现场送餐
   - 示例：乞丐在豪华酒店被赶出门
   - 示例：学生在黑帮谈判会上做作业

3. **商业Hook**：必须能让观众产生"我想看"的冲动
   - 示例：外卖员发现死者是自己的下一个订单客户
   - 示例：乞丐其实是隐藏的亿万富翁
   - 示例：学生其实是卧底警察

#### 2.1.2 生成规则

```
高反差公式：
[低位身份] + [高位场景] + [意外发现]

示例：
- 外卖员（低位） + 凶案现场（高位） + 发现死者是订单客户（意外）
- 乞丐（低位） + 豪华酒店（高位） + 其实是隐藏富豪（意外）
- 学生（低位） + 黑帮谈判（高位） + 其实是卧底（意外）
```

#### 2.1.3 验证标准

必须同时满足：
- [ ] 能用一句话概括（不超过20字）
- [ ] 包含两个极端元素（低位 vs 高位）
- [ ] 有意外发现（身份反转/秘密揭露）
- [ ] 能让观众产生"我想看"的冲动

#### 2.1.4 注入方式

**Bootstrap阶段**：
```json
{
  "core_hook": {
    "high_contrast": "外卖员 vs 连环杀手",
    "strong_visual": "外卖员在凶案现场送餐",
    "commercial_hook": "发现死者是下一个订单客户",
    "one_liner": "外卖员在凶案现场送餐，发现死者是订单客户"
  }
}
```

**约束注入**：
- 每2章必须推进core_hook的进展
- 不能偏离core_hook的核心吸引力
- 必须在第1章就展示core_hook

### 2.2 视觉锚点（Visual Anchor）

#### 2.2.1 定义

一个可拍摄的、极具视觉冲击力的画面，作为全剧的视觉符号。

#### 2.2.2 要求

1. **必须是物理的、可拍摄的**
   - ❌ "他很愤怒"（抽象）
   - ✅ "他的手指攥紧，指节发白"（物理）

2. **必须贯穿全剧（每3-5章出现一次）**
   - 第1章：首次出现，建立视觉记忆
   - 第3-5章：第二次出现，强化视觉符号
   - 第8-10章：第三次出现，成为剧情关键
   - 后续：反复出现，成为视觉锚点

3. **必须与core_hook强相关**
   - 如果core_hook是"外卖员在凶案现场送餐"
   - 视觉锚点可以是"黄色外卖箱"
   - 黄色外卖箱在凶案现场、警察局、医院、逃亡路上反复出现

#### 2.2.3 生成规则

```
视觉锚点公式：
[物理道具] + [场景对比] + [情感冲击]

示例：
- 黄色外卖箱（物理） + 凶案现场（对比） + 恐惧/紧张（情感）
- 破旧书包（物理） + 豪华酒店（对比） + 尴尬/自卑（情感）
- 学生证（物理） + 黑帮谈判（对比） + 危险/紧张（情感）
```

#### 2.2.4 验证标准

必须同时满足：
- [ ] 是物理道具（可拍摄）
- [ ] 能贯穿全剧（至少出现3次）
- [ ] 与core_hook强相关
- [ ] 有视觉冲击力（能引发情感反应）

#### 2.2.5 注入方式

**Bootstrap阶段**：
```json
{
  "visual_anchor": {
    "prop": "黄色外卖箱",
    "first_appearance": "第1章：外卖员背着黄色外卖箱出现在凶案现场",
    "recurring_frequency": "每3-5章出现一次",
    "emotional_impact": "恐惧、紧张、压迫感",
    "symbolic_meaning": "外卖员的普通身份 vs 不普通的遭遇"
  }
}
```

**约束注入**：
- 每3章必须出现visual_anchor的描写
- 必须在关键情节点出现
- 不能只是背景板，必须参与剧情

### 2.3 商业钩子矩阵（Commercial Hook Matrix）

#### 2.3.1 定义

从蒸馏数据中提取的、经过市场验证的钩子模式。

#### 2.3.2 数据来源

1. **yt-drama-ops蒸馏数据**（真实播放数据）
   - 包含5种核心骨架类型
   - 每种骨架有平均播放量、样本数量
   - 有心理学钩子和适用题材

2. **0xsline/short-drama**（钩子类型参考）
   - 悬念钩：抛出关键疑问，答案留到下一集
   - 反转钩：最后一刻颠覆观众预期
   - 情绪钩：情绪推到最高点然后切断
   - 信息钩：透露改变全局的关键信息，只说一半
   - 危机钩：突发重大危机，主角来不及反应

#### 2.3.3 五种钩子类型

**类型1：身份钩**
- 定义：主角隐藏真实身份，观众期待揭露
- 原理：观众享受"我知道你不知道"的优越感
- 示例：外卖员其实是前刑警
- 使用场景：起势段建立，风暴段揭露

**类型2：复仇钩**
- 定义：主角被伤害，观众期待反击
- 原理：观众享受"恶有恶报"的快感
- 示例：外卖员被冤枉，观众期待他洗清冤屈
- 使用场景：起势段建立，攀升段+风暴段释放

**类型3：悬念钩**
- 定义：抛出关键疑问，观众期待答案
- 原理：观众享受"解谜"的乐趣
- 示例：外卖员发现死者是订单客户，但为什么？
- 使用场景：每章结尾必须使用

**类型4：情绪钩**
- 定义：情绪推到最高点，观众期待释放
- 原理：观众享受"情绪过山车"的刺激
- 示例：外卖员被冤枉入狱，观众期待他翻案
- 使用场景：风暴段+决战段使用

**类型5：危机钩**
- 定义：突发重大危机，观众期待解决
- 原理：观众享受"紧张-释放"的循环
- 示例：外卖员被凶手追杀，观众期待他逃脱
- 使用场景：每章结尾使用

#### 2.3.4 注入方式

**Bootstrap阶段**：
```json
{
  "commercial_hooks": {
    "primary": ["身份钩", "悬念钩"],
    "secondary": ["复仇钩", "危机钩"],
    "usage": {
      "身份钩": "起势段建立，风暴段揭露",
      "悬念钩": "每章结尾必须使用",
      "复仇钩": "起势段建立，攀升段+风暴段释放",
      "危机钩": "每章结尾使用"
    }
  }
}
```

**约束注入**：
- 每章结尾必须使用指定的钩子类型
- 钩子类型必须与剧情阶段匹配
- 不能连续3章使用同类型钩子

### 2.4 创意碰撞引擎（Creative Collision Engine）

#### 2.4.1 定义

强制将两个不相关的元素碰撞，产生意外创意。

#### 2.4.2 碰撞公式

```
[题材A] × [题材B] × [商业Hook] = 高概念创意

示例：
- 外卖员 × 连环杀手 × 身份钩 = 外卖员其实是前刑警
- 甜宠 × 悬疑 × 复仇钩 = 女主以为在谈恋爱，其实是在被PUA
- 学生 × 黑帮 × 危机钩 = 学生其实是卧底警察
```

#### 2.4.3 生成规则

**步骤1：选择两个不相关的题材**
- 题材A：主题材（如：外卖员生活）
- 题材B：副题材（如：连环杀手）

**步骤2：选择商业钩子类型**
- 身份钩：主角隐藏真实身份
- 复仇钩：主角被伤害，期待反击
- 悬念钩：抛出关键疑问
- 情绪钩：情绪推到最高点
- 危机钩：突发重大危机

**步骤3：碰撞产生创意**
- 公式：[题材A] × [题材B] × [商业Hook]
- 示例：外卖员 × 连环杀手 × 身份钩 = 外卖员其实是前刑警

#### 2.4.4 验证标准

必须同时满足：
- [ ] 两个题材不相关（有反差）
- [ ] 商业钩子类型明确
- [ ] 创意有视觉冲击力
- [ ] 能让观众产生"我想看"的冲动

#### 2.4.5 注入方式

**Bootstrap阶段**：
```json
{
  "creative_collision": {
    "genre_a": "外卖员生活",
    "genre_b": "连环杀手",
    "hook_type": "身份钩",
    "collision_result": "外卖员其实是前刑警，因为三年前的车祸失去记忆",
    "alternative_collisions": [
      "外卖员其实是凶手的下一个目标",
      "外卖员其实是警察的卧底"
    ]
  }
}
```

**约束注入**：
- 碰撞方案必须贯穿全剧
- 不能偏离碰撞方案的核心
- 必须在关键情节点推进碰撞

def validate_core_hook(data: dict) -> bool:
    """验证高概念种子是否符合要求"""
    core_hook = data.get("core_hook", {})

## 五、风险控制
================================================================================

### 5.1 风险1：创意过于天马行空

**控制措施**：
1. 蒸馏数据验证：所有创意必须在蒸馏数据中有类似案例
2. 用户确认：Bootstrap阶段必须用户确认后才写入
3. 渐进式：先在小范围测试，验证效果后再推广

**验证方法**：
```python
def validate_creative_collision(data: dict, distill_data: dict) -> bool:
    """验证创意碰撞是否符合蒸馏数据"""
    collision_result = data.get("collision_result", "")
    
    # 检查是否有类似案例
    for skeleton_type, skeleton_data in distill_data.items():
        if collision_result in skeleton_data.get("examples", []):
            return True
    
    return False
```

### 5.2 风险2：实现复杂度高

**控制措施**：
1. 分阶段实现：先实现Phase 1，验证效果后再做Phase 2/3
2. 复用现有代码：尽量复用现有的constraint_injector和guardian框架
3. 简化版本：先做简化版本，只支持core_hook和visual_anchor

**简化版本**：
- Phase 1：只支持core_hook和visual_anchor
- Phase 2：添加commercial_hooks
- Phase 3：添加creative_collision

### 5.3 风险3：与现有系统冲突

**控制措施**：
1. 独立模块：高概念模式作为独立模块，不影响现有功能
2. 可选启用：用户可以选择是否启用高概念模式
3. 向后兼容：现有项目不受影响

**实现方式**：
```python
# 在bootstrap_response.json中添加开关
{
  "high_concept_mode": {
    "enabled": true,
    "components": {
      "core_hook": true,
      "visual_anchor": true,
      "commercial_hooks": true,
      "creative_collision": true
    }
  }
}
```
