# 高概念脑洞模式设计方案

## 问题诊断

传统AI跑大纲时的三大病灶：
1. **平庸化**：AI倾向于选择"安全"的、"最大公约数"式的创意，避免风险
2. **套路化**：AI会重复使用训练数据中常见的模式，缺乏突破性
3. **缺乏商业Hook**：AI不理解"什么能让观众点击"，只关注"逻辑自洽"

## 解决思路

在Bootstrap的第一秒，强制注入高反差、强视觉、极具商业Hook的创意结构。

### 核心理念

**创意结构 ≠ 剧情细节**

创意结构是骨架，剧情细节是血肉。AI可以自由发挥血肉，但骨架必须由人类设计或从蒸馏数据中提取。

## 设计方案

### 1. 高概念种子（Core Hook Seed）

**定义**：一句话描述故事的核心吸引力，必须包含：
- **高反差**：两个极端元素的碰撞（如：外卖员 vs 连环杀手）
- **强视觉**：必须能用一个画面概括（如：外卖员在凶案现场送餐）
- **商业Hook**：必须能让观众产生"我想看"的冲动

**示例**：
```
❌ 普通概念：外卖员卷入谋杀案
✅ 高概念：外卖员在凶案现场送餐，发现死者是自己的下一个订单客户
```

**注入方式**：
- Bootstrap阶段：强制生成core_hook字段
- 约束注入：每2章必须推进core_hook的进展

### 2. 视觉锚点（Visual Anchor）

**定义**：一个可拍摄的、极具视觉冲击力的画面，作为全剧的视觉符号。

**要求**：
- 必须是物理的、可拍摄的
- 必须贯穿全剧（每3-5章出现一次）
- 必须与core_hook强相关

**示例**：
```
《最后一单》视觉锚点：
外卖员的黄色外卖箱，在凶案现场、在警察局、在医院、在逃亡路上反复出现
```

**注入方式**：
- Bootstrap阶段：强制生成visual_anchor字段
- 约束注入：每3章必须出现visual_anchor的描写

### 3. 商业钩子矩阵（Commercial Hook Matrix）

**定义**：从蒸馏数据中提取的、经过市场验证的钩子模式。

**来源**：
- yt-drama-ops蒸馏数据（真实播放数据）
- 0xsline/short-drama（钩子类型参考）

**钩子类型**：
1. **身份钩**：主角隐藏真实身份，观众期待揭露
2. **复仇钩**：主角被伤害，观众期待反击
3. **悬念钩**：抛出关键疑问，观众期待答案
4. **情绪钩**：情绪推到最高点，观众期待释放
5. **危机钩**：突发重大危机，观众期待解决

**注入方式**：
- Bootstrap阶段：根据题材自动选择2-3个主要钩子类型
- 约束注入：每章结尾必须使用指定的钩子类型

### 4. 创意碰撞引擎（Creative Collision Engine）

**定义**：强制将两个不相关的元素碰撞，产生意外创意。

**碰撞公式**：
```
[题材A] × [题材B] × [商业Hook] = 高概念创意
```

**示例**：
```
外卖员 × 连环杀手 × 身份钩 = 外卖员其实是前刑警，因为三年前的车祸失去记忆
甜宠 × 悬疑 × 复仇钩 = 女主以为在谈恋爱，其实是在被PUA，发现真相后反杀
```

**注入方式**：
- Bootstrap阶段：自动生成3个碰撞方案供用户选择
- 约束注入：选定的碰撞方案必须贯穿全剧

## 实现路径

### Phase 1：Bootstrap增强（1-2天）

1. 修改bootstrapper.py，新增字段：
   - `core_hook`: 高概念种子
   - `visual_anchor`: 视觉锚点
   - `commercial_hooks`: 商业钩子矩阵
   - `creative_collision`: 创意碰撞方案

2. 修改bootstrap prompt模板，强制LLM生成这些字段

3. 添加验证逻辑，确保生成的字段符合要求

### Phase 2：约束注入增强（1天）

1. 修改constraint_injector.py，新增注入方法：
   - `_build_core_hook_injection`: 注入core_hook推进要求
   - `_build_visual_anchor_injection`: 注入visual_anchor描写要求
   - `_build_commercial_hook_injection`: 注入商业钩子使用要求

2. 修改build_injection_block，调用新方法

### Phase 3：Guardian增强（1天）

1. 修改guardian/__init__.py，新增检查：
   - `check_core_hook_progress`: 检查core_hook推进情况
   - `check_visual_anchor_presence`: 检查visual_anchor出现频率
   - `check_commercial_hook_usage`: 检查商业钩子使用情况

2. 添加警告和扣分逻辑

## 风险控制

### 风险1：创意过于天马行空

**控制措施**：
- 蒸馏数据验证：所有创意必须在蒸馏数据中有类似案例
- 用户确认：Bootstrap阶段必须用户确认后才写入
- 渐进式：先在小范围测试，验证效果后再推广

### 风险2：实现复杂度高

**控制措施**：
- 分阶段实现：先实现Phase 1，验证效果后再做Phase 2/3
- 复用现有代码：尽量复用现有的constraint_injector和guardian框架
- 简化版本：先做简化版本，只支持core_hook和visual_anchor

### 风险3：与现有系统冲突

**控制措施**：
- 独立模块：高概念模式作为独立模块，不影响现有功能
- 可选启用：用户可以选择是否启用高概念模式
- 向后兼容：现有项目不受影响
